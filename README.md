# weekly-dev-retro

> 주간 개발 회고를 "무엇을 했나"가 아니라 "무엇이 움직였나(지표)" 중심으로, 지난 주 KR 채점까지 포함한 md 문서로 써 주는 Claude 스킬

## 왜 만들었나
AI에게 주간 회고를 맡기면 커밋 메시지만 훑어 "무엇을 했다" 목록을 만들고, 재지 않은 수치를 실측처럼 쓰거나 지난 주에 세운 목표는 채점하지 않고 넘어가는 일이 반복됐다.
다른 사람의 커밋이 내 성과처럼 섞이거나, "개발한다" 같은 행동을 목표(KR)로 적는 일도 많았다.
그래서 커밋 diff를 직접 읽고, 실측값(0과 미측정 포함)으로 목표 → 실행 → 채점 → 다음 목표의 고리를 닫도록 절차와 형식을 고정했다.

## 언제 쓰나
- "이번 주 주간회고 써줘"
- "금요일 회고 준비해줘"
- "이번 주 작업 주간 공유용으로 정리해줘"
- "월요일 정렬 업데이트 해줘" / "현재 상황 채워줘"

## 무엇을 하나
- 직전 회고 이후 본인 커밋만 모아 diff를 읽고, 다른 사람 작업은 모든 섹션에서 뺀다
- 플랜·QA 체크리스트·회고 문서 등 작업 폴더의 산출물로 실측 수치와 전후 비교를 찾는다
- 새 집계가 필요하면 쿼리를 사용자에게 건네고 결과를 받는다. 받기 전 값은 **미측정**으로 남긴다
- 지난 주 KR을 하위 기준 문장 그대로 옮겨 달성 / 부분 달성 / 미달성 / 판정 보류로 채점한다
- 다음 주 KR은 "주말에 확인 가능한 결과 상태"(예: 배포 완료 + 오류 0건)로, 결과 확인 방법과 함께 쓴다
- 1절 완료 항목마다 속도·효율·오류 제거·설계·아쉬움 → 해결 꼬리표로 성공·실패 이유를 사실 근거로 적는다
- 노션에 그대로 붙여 넣을 수 있게 표 한 행을 한 줄로, HTML 태그 없이 쓴다

## 출력 예시
```
# 주간회고 — 홍길동 (2026-01-05 ~ 2026-01-09)

| 직무 | 공유할 내용 | 가져온 수치·근거 |
| --- | --- | --- |
| 백엔드 | 간편 주문 API dev 배포, 주문 목록 조회 속도 개선 | 커밋 12 · +840 / −210(25파일) · 목록 조회 3초 → 0.2초(dev) · 운영 오류 건수 **미측정** |

## 3. 개인별 금주 KR

#### KR ① 간편 주문 dev 배포 완료 + 아래 오류 발생률 0%

조회 범위: dev, 01-07 ~ 01-09 (운영 미배포)
판단: **부분 달성** — dev 배포·실측은 끝났고 구버전 앱 호환은 미측정

| 영역 | 항목 | 결과 | 시도 수 | 근거 |
| --- | --- | --- | --- | --- |
| 입력 | 상품당 사진 6장 이상 저장 0건 | 0건(dev) | 5케이스 | Swagger 실호출 |
| 호환 | 구버전 앱의 주문 등록 실패 0건 | **미측정** | — | 구버전 앱 빌드 확보 필요 |
```
